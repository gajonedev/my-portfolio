# Application mobile ou site web : par quoi commencer ?

« Il me faut une application. » Neuf fois sur dix, c'est la première phrase d'un porteur de projet. Et une fois sur deux, ma réponse honnête est : *pas si vite*. L'app mobile fait rêver, mais c'est parfois le mauvais premier investissement. Voici comment trancher — avec les critères que j'utilise réellement pour orienter mes clients.

## La différence fondamentale : l'accès

- Un **site web** est accessible instantanément : on clique sur un lien, c'est là. Zéro installation, zéro friction. Et Google le trouve.
- Une **application mobile** doit être découverte, téléchargée, installée — chaque étape perd des utilisateurs. En échange, elle vit sur le téléphone : icône visible, notifications, accès hors-ligne, matériel du téléphone (caméra, GPS…).

Toute la décision découle de cette différence.

## Choisissez le site web d'abord si…

- **Vos clients doivent vous trouver** : un site est référencé sur Google, une app ne l'est pas. Pour capter de la demande (« hôtel Ouidah », « boutique chaussures Cotonou »), le web gagne toujours.
- **L'usage est occasionnel** : personne n'installe une app pour consulter un menu ou demander un devis une fois par trimestre.
- **Vous vendez en ligne** : une [boutique web](/services/creation-ecommerce) touche tout le monde, y compris ceux qui n'installeront jamais votre app. L'app e-commerce viendra récompenser vos clients fidèles — plus tard.
- **Le budget est serré** : un [site professionnel démarre à 170 000 FCFA](/tarifs), une [application mobile à 900 000](/blog/combien-coute-application-mobile-benin-2026). Le web valide votre marché pour un cinquième du prix.

## Choisissez l'application mobile d'abord si…

- **L'usage est quotidien ou terrain** : gestion de commerce, suivi d'activité, outil d'agents sur le terrain — l'app dans la poche bat le site à chaque fois.
- **Le hors-ligne est vital** : au Bénin, un outil de terrain qui exige du réseau en permanence est un outil mort. Une app [offline-first](/blog/construire-app-sans-internet-offline-first) fonctionne partout et se synchronise quand elle peut — c'est impossible à égaler sur le web.
- **Les notifications sont le moteur** : rappels, alertes, relances — le levier d'engagement le plus puissant du mobile.
- **Vous utilisez le matériel du téléphone** en profondeur : scan, GPS temps réel, Bluetooth, capteurs.

## Le faux dilemme : « les deux, plus tard »

Le piège n'est pas de choisir le mauvais — c'est de vouloir les deux en même temps au lancement. Budget doublé, délais doublés, et vous ne savez pas encore ce que vos utilisateurs veulent vraiment.

Le chemin intelligent, que je recommande le plus souvent :

1. **Lancez sur un seul canal** — celui que les critères ci-dessus désignent
2. **Mesurez** ce que les utilisateurs font réellement
3. **Étendez** avec le second canal quand la demande le justifie — en réutilisant le [backend](/services/backend-api) déjà construit, qui sert les deux sans être refait

C'est exactement pour ça que je construis les backends séparés de l'interface : le moteur qui alimente votre site web aujourd'hui alimentera votre app Flutter demain, sans rien jeter.

## Et la PWA, l'entre-deux ?

Une Progressive Web App est un site web qui s'installe comme une app (icône, plein écran, un peu de hors-ligne). C'est un excellent rapport qualité/prix pour tester un usage « app » sans le budget mobile complet — mais avec des limites réelles sur iOS et sur les notifications. Bonne étape intermédiaire, rarement une destination finale.

## En résumé

| Votre priorité | Commencez par |
| -------------- | ------------- |
| Être trouvé par de nouveaux clients | Site web |
| Vendre en ligne | Site web (boutique) |
| Outil d'usage quotidien / terrain | App mobile |
| Fonctionner sans réseau | App mobile |
| Fidéliser par notifications | App mobile |
| Tester une idée à petit budget | Site web ou PWA |

Vous hésitez encore ? C'est normal — chaque projet a ses nuances. [Décrivez-moi le vôtre](/contact) : je vous dis franchement par quoi commencer, même si c'est l'option la moins chère. Un client bien orienté revient ; un client sur-vendu ne revient jamais.
